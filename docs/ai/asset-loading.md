# Game asset loading

`GameModelLibrary`, `GameTextureLibrary`, and `GameAudioLibrary` own reusable PlayCanvas assets. Texture and audio libraries share `AbstractGameAssetLibrary` for caching, concurrent request deduplication, four active loads per library, progress, retries, and teardown. Call `load()` before `get()`; objects borrow loaded assets and must not unload them.

After map preparation, `renderer.prepareMapAssets()` loads material textures, models, and the present objects' audio concurrently in one awaited asset phase. Renderer initialization only sets up the engine; rendering waits for all three asset types. The loading UI uses a separate `assets` phase (Loading assets) after map planning, then switches to `rendering` (Raising the terrain) only after asset loading finishes. Initial loading, navigation, and regeneration share these phase transitions. Materials and loaded assets are reused across maps; newly needed textures are attached to the existing materials, and failed loads can retry. Texture loads report `texture` progress. Named material textures retain separate sampler resources when the same image needs different wrapping or filtering. External shared model images are resolved through the texture library's image hook; declare their URL and image options under `src/game/textures/`.

Static shared images are entries in `textures/shared-textures.js`, without per-image wrapper classes. Its `woodTexture` binding supplies the common lighter, stylized door grain to furniture, shelter beams, door models, and runtime castle wood materials. Named `castleDoor` references and model image hooks share the same texture asset and repeat sampler. Other named textures retain their independent sampler resources. `textures/text/DynamicTextTexture.js` owns repaintable lettering for wooden signs and gateway labels; update its `text` property to reuse the canvas and GPU texture. `textures/heraldry/HeraldryTexture.js` owns the flag and banner drawing recipes and supports palette changes. Mutable providers belong to their consumer, which destroys them; do not share a mutable provider between independently editable objects. Cloth motion, meshes, materials, and interactions remain with the owning object.

Object classes declare `static audioUrls`. After map preparation expands generated objects, `MapObjectFactory.audioUrlsFor()` collects only present objects' audio. Await `renderer.prepareMapAssets()` before rendering a newly loaded map. Initial loading, route navigation, and regeneration do this and report `audio` progress. Constructors obtain assets from `runtime.audioLibrary`; repeated objects and subsequent maps reuse the decoded clip. Keep audio files under `src/game/audio/`. Preserve gesture-driven audio resume for browser autoplay rules.

Audio classes under `audio/` own their source URLs, for example `SignalBellAudio.wavUrl` and `.oggUrl`. Register these classes in `audio/audio-sources.js`; registration does not preload a sound. Objects declare and borrow audio through the class's `wavUrl` as the stable cache key. Keep WAV masters. `GameAudioLibrary` checks `audio/ogg; codecs="vorbis"` with `canPlayType`, prefers Ogg when supported, and falls back to WAV if unsupported or if Ogg download/decoding fails. Both formats share the same cached asset. Run `npm run audio:encode` with FFmpeg installed to regenerate Ogg Vorbis files at a nominal 192 kbps, using 48 kHz input for Vorbis bitrate support. Vorbis is variable bitrate; short/simple clips can average below the nominal rate. Encoding preserves channel count and leaves existing outputs intact if FFmpeg fails.

Future generated audio can live in its own provider class with generation and cleanup behavior, analogous to mutable texture providers. The current library loads file-backed audio; generated buffers will need a provider lifecycle integration when introduced.

Objects with contained runtime children can declare `static assetDefinitionsFor(definition)` so their children preload recursively; bowls use this for their contents. After all object preparation hooks expand generated children, `MapObjectFactory.assetsFor()` collects model and texture declarations only from classes present in the plan. Terrain textures follow the map tile types; hero, tools, inventory, bridge railings, and digging assets are included as runtime dependencies where applicable. Shared model images load through the model parser on demand. Navigation and castle replacement await discovery and loading before constructing the new scene. Asset caches persist across maps; leaving a map does not unload previously used resources. Class declarations may include multiple variants needed by that object class.

While a loading phase is active, `GameFrameLoop` cancels the pending PlayCanvas animation frame. Engine animation systems, physics, object update callbacks, and scene rendering stay paused; the loading UI and independent decoration queue keep running. After decorations finish, resume with a zero-delta engine frame before revealing the ready map, then restore the previous time scale. This avoids integrating time spent loading.
